# Indra Fine-tuning

Восстановление PyTorch-распознавателя [Indra OCR](https://github.com/datalab-to/indra),
дообучение на своих строках с CTC-loss и экспорт обратно в ONNX.

Это независимое расширение на основе Indra OCR 0.3.2. Исходный runtime,
история Git и Apache-2.0 лицензия сохранены. Код обучения добавлен в
`indra_ocr/finetune/`; это не официальный trainer Datalab.

## Возможности

- Восстановление обучаемой модели из `rec.onnx` и, при наличии, `model.safetensors`.
- Обязательная проверка совпадения сырых logits, IDs, confidence и длин с ONNX Runtime.
- Дообучение на UTF-8 JSONL: изображение строки и текст либо страница, bbox строки и текст.
- Baseline до обучения, валидация с CER/WER и продолжение с состоянием оптимизатора.
- Обучение на CPU, CUDA и Apple MPS (CTC на CPU с сохранением градиентов).
- Дисковый кэш строк без потерь и перемешиваемые батчи близкой ширины.
- Оценка целых страниц исходной и дообученной моделями с одинаковыми настройками.
- Расширение словаря с сохранением прежних IDs и весов классификатора.
- Экспорт с динамическими batch/width и запуск через обычный API Indra.

Обучается **основной распознаватель строк**. Детектор, порядок чтения,
отдельные модели китайского текста и формул не обучаются этим скриптом.

## Быстрый старт

Python 3.10+; локально проверен Python 3.13 на macOS CPU, CI настроен на Python 3.12/Linux.

```bash
git clone https://github.com/AigizK/indra-finetune.git
cd indra-finetune
uv venv --python 3.12 .venv
source .venv/bin/activate
uv pip install -e '.[train]'

indra-finetune download --out .model-source --revision v3.1.1 --with-safetensors
indra-finetune recover --source .model-source --out runs/recovered.pt
```

Вместо CLI можно использовать `python -m indra_ocr.finetune` с теми же аргументами.
Модели скачиваются с Hugging Face, веса и пользовательские датасеты в Git не включены.

## Формат данных

Одна строка JSONL — одна строка текста. Пути изображений считаются относительно manifest:

```json
{"image":"lines/0001.png","text":"Өфө — Башҡортостандың баш ҡалаһы."}
{"image":"pages/page01.png","bbox":[120,240,970,276],"text":"Башҡорт телендәге тексты таныу"}
```

Изображения строк должны быть обрезаны близко к чернильной области.
`bbox` — `[x0,y0,x1,y1]` в пикселях исходной страницы. Скрипт применяет тот же
`crop_line`, что и оригинальный OCR: поля, высота 32, ink map и дополнение справа.
Для скорости обучения удобнее заранее сохранить отдельные изображения строк.

Разделяйте train/valid/test **по документам**, чтобы строки одной страницы не
оказались в разных выборках. Неизвестные символы, пустые тексты, некорректные
изображения и невозможные для CTC транскрипции вызывают явную ошибку.

## Дообучение и экспорт

```bash
indra-finetune train \
  --checkpoint runs/recovered.pt \
  --train data/train.jsonl --valid data/valid.jsonl \
  --out runs/bashkir --cache-dir .line-cache \
  --epochs 10 --batch-size 8 --lr 0.0001 --device auto

indra-finetune export \
  --checkpoint runs/bashkir/best.pt \
  --base-model-dir .model-source --out runs/bashkir-model \
  --manifest data/valid.jsonl

indra-ocr scan.png --model-dir runs/bashkir-model
```

`auto` выбирает CUDA → MPS → CPU. На Apple Silicon нейросеть может обучаться на
GPU (`--device mps`), а CTC считается на CPU; градиент возвращается на GPU.
`--device cpu` оставляет весь процесс на CPU.
Новые символы можно добавить флагом `--extend-vocab`; буквы
`Әә Өө Үү Ҡҡ Ғғ Ҙҙ Ҫҫ Ңң Һһ` уже есть в исходном словаре.

В папке запуска сохраняются `baseline.json`, `last.pt`, `best.pt`, `metrics.jsonl`
и `arguments.json`. Baseline измеряется на входном checkpoint до расширения
словаря и до первого шага оптимизатора. С `--valid` лучшая модель среди эпох
текущего запуска выбирается по CER. Без него — по train loss,
без оценки качества на новых документах. Папки запусков и экспорта должны быть новыми.
`best.pt` сохраняется и при отсутствии улучшения относительно baseline;
флаг `improved_over_baseline` в метриках показывает результат сравнения.

## Кэш и батчи

`--cache-dir .line-cache` сохраняет float32 ink maps в `.npy` без потерь.
Ключ зависит от содержимого изображения, bbox, высоты и кода препроцессинга.
Изменение исходных данных создаёт новую запись. На первом проходе каждая страница
декодируется один раз; на следующих запусках читаются готовые строки, а не страницы.
Весь датасет не загружается в RAM. Кэш требует места на диске: например,
10 тысяч строк `32×1024` занимают примерно 1.3 ГБ без учёта заголовков файлов.

Предварительное заполнение кэша:

```bash
indra-finetune cache-lines --manifest data/train.jsonl --cache-dir .line-cache
```

Группировка по ширине включена по умолчанию. Каждый пример используется ровно
один раз за эпоху, порядок батчей и примеров равной ширины перемешивается.
Лимиты: `--max-width-ratio 1.3` и `--max-batch-area 40960` (сумма дополненных
ширин в батче). `--no-width-buckets` возвращает обычные случайные батчи.

## Оценка целых страниц

Отдельный JSONL содержит полную транскрипцию каждой страницы, без bbox:

```json
{"image":"pages/page01.png","text":"Первая строка\nВторая строка"}
{"image":"book.pdf","page":3,"text":"Текст четвёртой страницы PDF"}
```

```bash
indra-finetune evaluate-pages \
  --manifest data/test-pages.jsonl --model-dir .model-source \
  --compare-model-dir runs/bashkir-model --out runs/page-evaluation
```

Команда запускает полный OCR, включая детектор и порядок чтения. По умолчанию
`--mode ocr` принудительно распознаёт и цифровые PDF; колонтитулы сохраняются.
Обе модели получают одинаковые режим, DPI и нормализацию (`--normalization NFC`
или `NFD`). Результаты: `baseline.jsonl`, `candidate.jsonl`, `report.json`
с micro CER/WER, macro CER, долей полностью правильных страниц и разницей CER/WER.
Отрицательная разница означает улучшение. Регистр, пунктуация и внутренние
переносы/пробелы учитываются; удаляются только внешние пробелы.

Страницы с ошибкой остаются в отчёте и в знаменателе метрик с пустой гипотезой;
команда завершается с ошибкой, чтобы неполный прогон не считался успешным.
Для многостраничного файла обязателен явный `page` с нумерацией от нуля.

[Подробная инструкция](FINETUNING_RU.md) описывает resume, проверки, ограничения
препроцессинга, расширение словаря и формат checkpoint.

## Проверки

Локально на исходных весах `v3.1.1` восстановлены **1 236 110 параметров**.
В тестовых батчах IDs и длины совпали с ONNX; максимальное расхождение logits
составило около `1e-4`. Проверены CTC backward, расширение словаря, продолжение
с оптимизатором, экспорт и загрузка через публичный `OrtOCR`.

[Отчёт проверки](FINETUNING_VALIDATION.json) фиксирует версии библиотек,
SHA256 исходных весов и метрики smoke-теста. Совпадение train/valid в этом
smoke-тесте намеренное: он проверяет механику, а не обобщающую способность.
Проверки версии 0.2 дополнительно покрывают инвалидацию кэша, batching,
совпадение resume с непрерывным обучением, MPS backward и оценку целых страниц.
MPS-тест требует Apple GPU и пропускается в Linux CI.
Локально на версии 0.2 прошли все 42 теста, включая настоящий MPS.
Отдельно выполнен полный цикл на демонстрационных рукописях: обучение на MPS,
resume, экспорт и сравнение целых страниц. [Отчёт версии 0.2](WORKFLOW_VALIDATION.json).

```bash
uv pip install -e '.[train,test]'
python -m pytest -q
```

Без `.model-source/rec.onnx` два integration-теста пропускаются. Для полного
прогона скачайте модель командой `download` выше. GitHub Actions делает это автоматически.

## Планирование башкирского дообучения

Оценка для печатного текста: 1–2 тысячи строк для пилота, 5–10 тысяч для
одного типа документов, 20–50 тысяч для разных шрифтов и качества сканов.
Это ориентиры для эксперимента, а не измеренные пороги качества Indra.
Отдельно резервируйте validation/test и проверяйте ошибки на редких буквах.

На Apple M4 Pro, CPU с двумя потоками, батч 8, высота 32 и ширина 512–1024
замерено примерно 59–72 строки/с обучения при 82 токенах на строку, без I/O,
валидации и сохранения checkpoint. Пиковая RAM процесса — около 0.4–0.6 ГБ.
Точные результаты — в [CPU_BENCHMARK.json](CPU_BENCHMARK.json).

## Ограничения и происхождение

Восстановлена эквивалентная вычислительная модель опубликованного ONNX.
Часть BatchNorm уже объединена со свёртками: исходную структуру до экспорта,
статистики этих BN, optimizer и оригинальный рецепт обучения вернуть нельзя.
Объединённые свёртки остаются обучаемыми; running statistics оставшегося
stem BatchNorm фиксированы при fine-tuning.

Восстановление и тестовое обучение проверяются на CPU и MPS. CUDA поддержана кодом,
но её скорость и память локально не измерялись. Качество на реальных башкирских
документах пока не измерено. Исходная модель ориентирована на чистый печатный текст.

Код распространяется по [Apache-2.0](LICENSE). Веса Datalab скачиваются отдельно
и используют [собственную лицензию](https://huggingface.co/datalab-to/indra-ocr/blob/main/LICENSE).
Атрибуция и изменения перечислены в [NOTICE](NOTICE); оригинальная документация —
